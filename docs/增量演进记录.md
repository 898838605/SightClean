## v1.3 · 三个模块的加入

### 底线：增量，不重写

| 允许 | 不允许 |
|---|---|
| 给现有类加字段、加方法、加可选参数 | 改现有公开方法签名（必须加时要有默认值） |
| 在现有方法里追加分支 | 把方法体整段替换 |
| 新增文件、新增类 | 删除或重写现有核心逻辑 |
| 调整 UI 容器结构 | 改动现有业务行为 |

**具体做法**：`main_window.py` 里文件逻辑一行不删，只是把 splitter 从 `setCentralWidget()` 改放进 `QStackedWidget` 的第 0 页。

**没做的事**：没把 90 KB 的 `main_window.py` 拆成四个 Controller——那是重写。新模块用 `page_base.py` 的 `ModulePage` 基类承载。

### 三个模块各自的难点

**软件卸载**

- 单一数据源有盲区 → 三源合并（注册表 / winget / 孤儿），注册表优先
- winget 输出是等宽表格，中英文混排列会错位 → 按 `east_asian_width` 切，不能按空格
- MSI 的 `/I{GUID}` 是**安装**参数，卸载必须换 `/X{GUID}`（这台机器 17 处）

**注册表清理**

- 删键和删值是两个不同操作 → `registry.py` 和 `regvalue.py` 分开
- 删除前必须备份，且备份的是**整个子树**（`reg export` 天然就是整棵）

**进程管理**

- 系统进程只标红、不阻止勾选——决定权在用户
- 结束要"先礼后兵"：`terminate()` → 等 1 秒 → 还活着就 `kill()`

## v1.4 · 两个「按规则批量清」的功能

### 注册表失效项扫描

**需求**：参考 Windows Maintenance Tool 的清理规则，做一键清注册表。

**核心判断**：那个项目是 3.1 MB 的 PowerShell 单文件，抓取被截断读不全。但它那类工具的核心原则是通行的——**不做主观猜测，只做客观核对**。

一个注册表项如果**指向的东西已经不存在**，那它一定无效。

| 类别 | 判断依据 |
|---|---|
| App Paths | 登记的 exe 找不到了 |
| 卸载登记 | 安装目录、图标、卸载程序**全都不在** |
| SharedDLLs | 引用的 DLL 文件不在了 |
| Run / RunOnce | 指向的程序不在了 |

**明确不做**：看起来像垃圾的键、很久没改过的键、**空键**（有些程序先建空键再填）。

**踩的坑（最值得记）**

异常码有歧义：

```
winerror 5  →  下面有子键   或   真的没权限
winerror 2  →  真不存在     或   没权限被伪装成不存在
```

一开始直接把 `FileNotFoundError` 翻译成"这一项已经不在了"，导致错误归因。

修法分两步：

1. **先判存在，再判权限**——顺序反了会把"不存在"报成"没权限"
2. **失败后回头查状态**——`_diagnose()` 看这个键还在吗、能读吗、几个子键

**第二个坑：WOW64 视图**

`HKLM\...\SharedDLLs` 在 32/64 位视图下是**两个不同的键**：

```
64 位视图        97 个值
32 位视图       113 个值
只在 32 位里的   25 个
```

用 `KEY_WOW64_32KEY` 打开时，实际读的是 `WOW6432Node` 那条，但**手里的路径字符串还是不带 WOW6432Node 的**。删除时按那个字符串打开，拿到的是另一个键 → 报"已经不在了"。

修法：**扫描时不用 WOW64 标志**，直接写两条真实路径。

顺带修掉重复计数——两个视图各扫一遍，98 项里 59 项是重复的，去重后 39 项。

### 一键清理 C 盘垃圾

**需求**：规则写 JSON，默认五类（临时文件、系统日志、缩略图缓存、浏览器缓存、包管理器缓存）。

**设计尺度**（这一类最容易变成"替用户做主"）：

| 规矩 | 原因 |
|---|---|
| 只扫规则里写死的类别 | 用户能预料它会动什么 |
| 每类写清「删了会怎样」 | 删之前就知道后果 |
| 默认只勾 safe | caution 的（系统日志）要主动勾 |
| 被占用的跳过 | 卡住比强删好 |
| **按类别勾，不逐条列** | 十几万项没法看 |

最后一条是改出来的：第一版逐条列，扫描 23 秒、7761 行——列表既没法看又卡。改成按类别汇总后，扫描 5.3 秒、5 行。

**优化**：一次遍历同时数个数和大小，别开两遍。

**路径显示**：每类下列出实际路径，**双击能跳资源管理器**。

记录"扫的是哪些位置"时踩了个坑——最初把每个子项都记成路径，临时文件那一类记了 **35504 条**。改成记录**源目录**才对。

## v1.5 · 空闲进程清理

### 需求变了两次

**第一版**：「找出既不属于系统、也不属于已装软件的进程」

结果 75 个候选，全是误报——`Common Files` 里的共享组件、`WindowsApps` 的商店应用、`Program Files` 里没登记路径的软件。

三层过滤降到 13 个：

1. 排除 `Common Files` / `WindowsApps`
2. 凡在 `Program Files` 下的一律算已装软件
3. 路径里含已装软件名的也算

**第二版**：「不属于**正在运行**的软件」——差一个词，判断依据完全不同。

「已安装」是静态的（路径在哪），「正在运行」是动态的（**父进程还在不在**）。

```python
if proc.ppid and proc.ppid in alive and proc.ppid not in adopted_pids:
    continue   # 父进程还活着，它是那个程序的一部分
```

改完 13 个 → 0 个（这台机器确实没有孤儿进程）。

**第三版**（最终）：按「开了多久 + 在不在前台 + CPU」找**忘了关**的进程。

### 三层排除系统进程

**第一层：会话 ID**

Windows 用会话隔离服务和用户程序：

```
会话 0    = 服务会话（WUDFHost、spoolsv、vmms、各种厂商服务）
会话 1+   = 用户登录会话
会话 -1   = 查不到（受保护进程）
```

比看用户名靠谱——普通权限也能查，服务一律在 0。

**第二层：桌面 shell 名单**

`explorer.exe`、`StartMenuExperienceHost.exe`、`SearchHost.exe`、`ShellHost.exe`、`WidgetBoard.exe`……动了这些，任务栏和桌面直接没了。

**第三层：父进程**

微信拉起 9 个 `WeChatAppEx.exe`、WorkBuddy 拉起 `node.exe`——这些属于正在运行的软件。

`_ADOPTED_PARENTS` 里的（`explorer.exe`、`cmd.exe`、`svchost.exe`）拉起的算"独立启动"。

**最终结果**：91 个候选，全是用户程序（Edge 14 个、WorkBuddy 11 个、VSCode 10 个……）。

### 界面细节

**判据要摆在明面上**：

```
☐ msedge.exe　12 个进程                    开了 3.2 小时　CPU 0.3%
```

时长和 CPU 都显示，用户看着数据决定。

**踩的坑**：右侧标签一开始被挤扁，显示成 `开了 3.2 小时  CPU`——数值被右边缘吃掉。

修法：

```python
stat.setMinimumWidth(210)
stat.setSizePolicy(QSizePolicy.Fixed, QSizePolicy.Preferred)
head.addWidget(stat, 0)     # 0 = 不参与拉伸
```

## v1.6 · 改名和修补

### 改名 SightClean

`磁盘清理助手` → `SightClean`，涉及 14 处代码 + spec + 文档。

**漏网之鱼**：`build.bat` 是 **GBK 编码**，批量替换脚本按 UTF-8 读写，跳过了它。

### 图标接入

`QApplication.setWindowIcon()` 是**应用级默认图标**，所有没单独设图标的窗口自动继承——包括 `QMessageBox`、`QFileDialog`、设置窗、各种清理对话框。

**栽的坑**：spec 里为了省体积把 `imageformats\` 整个剔了，而 `qico.dll` 就在里面。

`QIcon` 加载失败**不抛异常**——只是变成空图标，标题栏悄悄退回默认图标，完全没有报错线索。

排查过程也绕：`%TEMP%` 里堆了 30 个历史 `_MEI*` 解包目录，`Select-Object -First 1` 按名字排序取第一个，拿到的往往是旧的，一度以为资源没打包。

改成按时间取最新才对：

```powershell
| Sort-Object LastWriteTime -Descending | Select-Object -First 1
```

### AI 结果两类丢失

**问题一**：点「识别本页未知项」后作用列没反应。

发给 AI 的是 **exe 路径**（PID 对它没意义），回填却按 PID 找——永远找不到。

修法：`update_ai_by_exe()`，按 exe 匹配，同一程序多个实例一起更新。

**问题二**：结束一个进程后，之前识别出的作用变空了。

`refresh()` 从知识库重建所有行，AI 结果被覆盖。

修法：`_ai_memory` 按 exe 路径记住结论，重建行时套回去。

```python
remembered = self.model.memory_of(item.exe or item.name)
if remembered is not None:
    row.effect = remembered[0]
    row.source = "ai"
    # AI 只能把风险说得更严，不能把红色的说成安全
```

### 其他修补

| 问题 | 修法 |
|---|---|
| 「设置」挤在工具栏 | 移到菜单栏「工具」和「帮助」之间 |
| 按钮文案不准 | 「扫描残留文件夹」→「AI 扫描卸载残余文件夹」，提示只留一句 |
| 垃圾清理要能查看 | 每类下列路径，双击跳资源管理器 |
| AI 要先刷新软件页 | 程序自己读，60 秒缓存 |
| 名称列拖不动 | `Stretch` → `Interactive` |
| 列表刷新后还是空的 | `set_pending("")` 屏蔽信号，要手动调 `model.set_filter("")` |

## 走过的弯路

| 弯路 | 教训 |
|---|---|
| 逐条列 7761 个垃圾项 | 聚合视图比明细有用 |
| 用 `os.path.exists` 判命令是否存在 | 要区分"路径"和"命令名"（`MsiExec.exe` 得去 PATH 里找） |
| 把服务当成"忘了关的软件" | 会话 ID 是最可靠的区分方式 |
| 按 PID 缓存 AI 结果 | PID 会变，exe 路径才稳定 |
| 整个目录剔 Qt 组件 | 要精确到文件，`QIcon` 失败不报错 |
| 用关键词过滤看测试失败 | 会漏掉语法错误（没有 `FAIL:` 行） |
| `Select-Object -First 1` 取临时目录 | 要按时间排序，否则拿到历史残留 |
| 相信"偶发失败"这个判断 | 先看完整堆栈，再下结论 |

## 版本间的关系

每一版都是**在上版基础上加东西**，没有推倒重来：

- v1.2 → v1.3：三个新模块，文件模块行为契约不变
- v1.3 → v1.4：新增两个批量清理入口，不动原有判定
- v1.4 → v1.5：进程模块的判据重写，其他模块不动
- v1.5 → v1.6：只改名、换图标、修 UI 细节

**唯一一次推倒重来**是进程清理的判据——从"路径判定"换成"父子关系 + 会话 ID"，因为需求从"不是已装软件的进程"变成了"不是正在运行软件的进程"。这两个目标看着相似，判断依据完全不同。
