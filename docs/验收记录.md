## 三、知识库格式（schema 3）

规则字段：

```json
{
  "id": "win-update-download",
  "layer": 1,
  "pattern": "\\softwaredistribution\\download\\",
  "match": "path_contains",
  "effect": "Windows 更新下载到本地的安装包，装完就没用了。",
  "impact": "删了不影响系统，下次更新会重新下载",
  "risk": "safe",
  "source": "builtin"
}
```

**当前规模**：87 条规则

| 层 | 条数 | 作用 |
|---|---|---|
| layer 1 | 38 | 路径特征（最准） |
| layer 2 | 38 | 文件名 / 扩展名 |
| layer 3 | 11 | 兜底 |

**七种匹配方式**

`path_contains`、`path_regex`、`ext`、`name_contains`、`name_exact`、`key_prefix`、`key_contains`

**匹配顺序**：user 规则整体优先 → layer 1 → 2 → 3 → 同层按数组顺序 → 先命中先用。

**风险四档**

```
safe       放心删   绿
caution    看情况   黄
forbidden  别删     红
unlisted   未收录   灰
```

### 「未收录」用灰色的决定

需求里写了「匹配不上返回 risk=caution」，同时提出「未收录建议用灰色而非黄色，避免误导」。

采纳后者，实现上分两层：

- **对外契约**（`match()` 的返回值）保持 `risk = "caution"`、`source = ""`，按需求写的调用方行为不变
- **显示层**用灰色 + 「未收录，建议确认后再删」，不用醒目的黄色

## 五、这一版修掉的问题

记录一下踩过的坑，避免以后再犯。

### 5.1 静默失败类

| 问题 | 现象 | 根因 | 修法 |
|---|---|---|---|
| 图标不显示 | 标题栏是默认图标 | spec 里把 `imageformats\` 整个剔了，`qico.dll` 是读 ico 的必需品 | 只剔不用的格式，保留 qico |
| AI 结果不落地 | 点识别「作用」列没反应 | 发给 AI 的是 exe 路径，回填却按 PID 找 | 加 `update_ai_by_exe`，按 exe 匹配 |
| AI 结果刷新就丢 | 结束进程后作用列变空 | `refresh()` 重建行时被知识库覆盖 | 加 `_ai_memory`，按 exe 记住结论 |
| 刷新不生效 | 点刷新列表还是空的 | `set_pending("")` 屏蔽信号，模型过滤词没清 | 三个页面都手动调 `model.set_filter("")` |

### 5.2 错误归因类

| 问题 | 报的什么 | 真实原因 | 修法 |
|---|---|---|---|
| 注册表删不掉 | 「没有权限」 | `winerror 5` 有两义：下有子键 / 真没权限 | `_diagnose()` 回头查键的状态再说 |
| 注册表删不掉 | 「已经不在了」 | 32 位视图的键路径没带 `WOW6432Node` | 扫描用显式路径，不用 WOW64 标志 |
| 值删不掉 | 「已经不在了」 | 先判权限后判存在，顺序反了 | 先 `read_value` 确认存在，再判权限 |
| 进程清理崩 | TypeError | 给 `kill_process` 传了整个对象而不是 pid | 传 `proc.pid, proc.name` |

### 5.3 规则设计类

| 问题 | 现象 | 修法 |
|---|---|---|
| 孤儿进程误报 75 个 | `Common Files`、`WindowsApps` 里的共享组件被当成孤儿 | 加共享目录排除 |
| 服务进程混进空闲列表 | WUDFHost、spoolsv 被当成「忘了关的软件」 | 按会话 ID 过滤（服务在 0） |
| 微信插件被当成孤儿 | 9 个 `WeChatAppEx.exe` | 按父进程过滤：父进程还活着就不算 |
| 共享 DLL 重复计数 | 两个 WOW64 视图各扫一遍 | 用显式路径，去重 |

## 六、已知限制

| 限制 | 说明 |
|---|---|
| 文件锁检测只能启发式 | 靠「进程 exe 在目标目录下」猜，猜不到「进程打开着目录里的文件」 |
| 卸载「成功」= 卸载器启动了 | 不代表软件真被移除，文案始终是「已启动」而不是「已卸载」 |
| 孤儿进程依赖父子关系 | 父进程已退出的才算，孙子进程可能漏掉 |
| AI 判断有波动 | `temperature` 默认 0.1 已尽量压低，但不是 0 |
| 未覆盖的位置 | `HKLM\SYSTEM\...\Services`、计划任务、防火墙规则、驱动文件 |
